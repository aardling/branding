Mobile first

  1. Everything tokens.css declares in :root — type sizes, spacing, containers, the page margin — is the value for a 360px screen.
  2. Every media query is min-width, and restates only what changes at that width.

Web Mobile first, continued

Mobile first, in practice

360px first

  1. Design at 360px first. Not 375, not 390.
  2. Check the hero, the navigation and any table at 360px before a desktop viewport.

No custom property in a media query

  1. @media (min-width: var(--breakpoint-lg)) fails silently in every browser.
  2. The breakpoint tokens are for JavaScript and for keeping the two token files in step.
  3. In a query, write the literal.

Web Focus, links, controls

Focus and links

  1. Anything that reacts to a pointer reacts to the keyboard the same way.
  2. No information, control or navigation exists only in a hover state.

Focus ring

Book a call On Violet On Night Blue
  1. 3px solid, offset 2px, on :focus-visible.
  2. Night Blue on every light ground, Snow White on every dark one.
  3. Night Blue is the only palette colour that clears 3:1 on all eight approved grounds. Ocean Blue fails on Violet (2.33), Pink (2.37) and Hover Green (2.66).
  4. Never outline: none without a replacement in the same rule.

Links

  1. A link is always underlined. The underline is the only thing that marks it.
  2. Link colour never changes on hover, at any size.
  3. The underline stays 1px and goes from --link-underline, a 50% tint, to full colour on hover.

We ran a three-day modelling workshop with their platform team, and it brightens on hover.

Visited links are not styled: there is no approved pair for a third text colour.

Web Motion, elevation

Motion and elevation

Motion

--duration-fast120msColour changes: hover, focus, active.
--duration-base240msAnything that moves, resizes or fades: disclosure, drawer, menu.
--ease-standardcubic-bezier(0.2, 0, 0, 1) — every transition, both durations.
  1. One easing curve for every transition.
  2. The tokens collapse to 1ms under prefers-reduced-motion. Anything animating without them is stopped by hand.
  3. Nothing animates on load. The page arrives at rest.
  4. Animate transform and opacity only.

Elevation

--shadow-raised
A card or panel at rest.
--shadow-overlay
A menu, a dialog, a sticky bar.
  1. Shadows are cast in Night Blue, never black.
  2. Two steps, no third.
  3. On the dark ground --shadow-raised is none; the surface colour lifts the card.

Web Dark mode

Dark mode

  1. The operating system decides. One prefers-color-scheme: dark block re-points the ten roles.
  2. No theme toggle, nothing remembered between visits.
  3. The palette does not change between themes; --text-primary and the other roles resolve differently.
  4. Components reference roles, never palette colours. A component that needs its own dark-mode CSS is a bug.

Domain Modelling

Untangle complex business domains and make your architecture work for you. Secondary text 6.57, hairline 1.65. A card lifts to #242942, with no shadow.

Web Dark mode, continued

Pastels

  1. Violet, Lime Green, Yellow and Pink take only Night Blue, and measure the same in both themes.
  2. A pastel section and the primary button are identical in both themes.

Surface attribute

  1. A pastel section on a dark page carries data-surface="light". Without it a focus ring here inherits Snow White and measures 1.69.
  2. An inverted section, such as the footer, carries data-surface="dark".
  1. light and dark are the only values. data-surface is the only attribute this brand styles.
  2. Artwork has no dark variant: the four gradients and the illustrations are the same files in both themes.
  3. Check both themes before calling anything finished, by switching the operating system setting. A devtools override misses the scoped case.
